## 5. 命令手册（全部在 nix devshell 内）

```bash
SC=$ROOT/vie/work/AES/spec-check
BIN=$SC/target/debug/cargo-spec-check
CV=$VERUS_SDK/target-verus/release/cargo-verus
Z3=$VERUS_SDK/z3; VSTD=$VERUS_SDK/vstd

# 1) 规格普查（纯 VIR，秒级）
$BIN census --vir /tmp/vir-export/crate.vir --crate ostd \
  --out /tmp/census --source-root /tmp/vostd-43da079-ktest-chan

# 2) requires 全函数筛查 + E6 信号（离线；--config/--expectations 为项目侧输入）
$BIN screen-requires --census /tmp/census/census.json --out /tmp/screen \
  --config $SC/examples/vostd-requires/config-projections.json \
  --expectations $SC/examples/vostd-requires/e6-expectations.json \
  --batch 15 --batch-size 50 \
  --cargo-verus $CV --z3 $Z3 --vstd $VSTD

# 3) 对已有运行重算 E6 信号（不重跑）
$BIN signals --screening /tmp/screen/screening.json \
  --verdicts /tmp/screen/run/verdicts.json --out /tmp/screen/signals.json

# 4) 量化器/构造 vacuity 探针
$BIN analyses-vacuity --manifest $SC/examples/vostd-guard/full-manifest.json \
  --cargo-verus $CV --z3 $Z3 --vstd $VSTD --out /tmp/vac

# 5) 义务 client 对照（divergence）
$BIN analyses-divergence --manifest $SC/examples/vostd-divergence/divergence-manifest.json \
  --cargo-verus $CV --z3 $Z3 --vstd $VSTD --out /tmp/div

# 6) ktest 断言 → 义务候选
$BIN extract-ktest --source-root /tmp/vostd-43da079-ktest-chan/ostd/src \
  --out /tmp/ktest-candidates.json \
  --config $SC/examples/vostd-ktest/extract-config.json --stats /tmp/ktest-stats.json

# 7) candidates + recipes → divergence manifest（合成器）
$BIN synthesize --candidates /tmp/ktest-candidates.json \
  --recipes $SC/examples/vostd-ktest/recipes-m7b.json \
  --out /tmp/manifest.json --report /tmp/synth-report.json

# 8) 台账对账（只提案，不改 registry）
$BIN ledger --registry $ROOT/vie/work/AES/research/experiments/spec-quality-two-day/findings/registry.json \
  --report /tmp/vac/report.json --report /tmp/div/report.json \
  --out /tmp/ledger

# 9) check 流程（capture + 多分析，一条命令）
$BIN check --project /tmp/check/project.json \
  --cargo-verus $CV --z3 $Z3 --vstd $VSTD --out /tmp/check/out

# 10) 本地==CI 入口（vostd 首站）
VOSTD_DIR=$ROOT/vie/work/AES/vostd \
SPEC_CHECK_CARGO_FLAGS=--offline \
SPEC_CHECK_NO_NIX=1 \
$SC/examples/ci/run-spec-check.sh
# 可选 census：加 SPEC_CHECK_CENSUS=1（需要 cargo dv；默认关）
```

## 8. 纪律与坑（务必保持）

1. **预注册纪律**：EXPECTED/预测先写，运行后不改写；不一致本身就是 E6 信号。
2. **健全性分层**：`ConfirmedVacuous` 是模型相对判定；只有 faithful/over-approx 模型上的
   Vacuous 可作候选证据；抽象上的 `ConfirmedLive` **不是**真实 liveness。
3. **Inconclusive 不计缺陷**；`CandidateInconclusive`/`Candidate` 一律需人工裁定。
4. **requies 必须写成具名 spec fn 应用**，字面比较会触发推断失败（"Could not infer triggers"）。
   量化 projected 子句要用 named uninterp，否则 trigger 失败。
5. **cargo-verus 缓存**：`--log vir` 可能什么都不写（换新 log-dir；必要时删 fingerprint）。
6. **注入恢复**：analysis 会向 manifest 的 `target_workspace` 注入 `spec_check_probes/`
   并在结束时恢复；崩溃后先检查残留（`ostd/src/spec_check_probes`、lib.rs 声明）。
7. **退出码契约**：发现不置红；只有管道失败非零。
8. **工具零项目专有知识**：vostd 类型/配方/投影模型全部在 `examples/` 的项目侧输入。
9. **vostd 工作树是 dirty 的**（先期改动），不要 `git add -A`、不要 reset。
10. 台账维护：新发现按 `dedup_key` 去重；证据追加可自动提案（ledger），**状态转移人工**；
    `upstream_merged` 属外部信息，工具不探测。
